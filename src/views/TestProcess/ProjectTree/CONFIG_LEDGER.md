# 项目树功能与配置台账

## 使用方式

选择项目 →「功能与配置台账」→「版本与历史」。已有旧便签先点击「历史整理预览」，核对前后内容后点击「应用本次整理」。预览有效期 20 分钟；报告或便签变化后需重新生成。预览不会写入数据库，应用时保留原始便签归档。

首次整理后，新增报告沿用原有项目树分析入口自动同步；报告修订会在打开/刷新项目树时后台核对，也可点击「同步报告变更」立即处理。后台核对完成后需刷新查看结果。AI 失败时不保存本次分析结果，原记录保留，可再次同步。

## 判断约定

| 情况 | 台账处理 |
| --- | --- |
| 新增功能、需求、行为或配置，没有明确数值 | 收集完整规则，不猜测值 |
| Bug、修复记录、测试结论、项目背景 | 不收集为配置；人工原始便签仍保留 |
| Bug 文本包含明确应有配置 | 只收集应有配置，不采用错误表现 |
| 新版本未提及旧功能 | 继承 |
| 同版本再次提交 | 增量修正，未提及的功能保留 |
| 明确废除功能 | 当前记录标为废除，历史仍可查看 |
| 关闭功能 | 配置值调整，不当成废除 |
| 功能名称相似度大于 80% | 群体、平台、A/B 一致时匹配；歧义保留独立项并提示 |
| 自然量调整、归因未变 | 仅调整自然量项 |
| 手工复合配置便签 | 先拆分功能与群体，再参与更新，保留原文历史 |
| 报告版本低于台账最高版本 | 项目树提示，不覆盖最新台账 |

为保持修改范围，低版本提示仅在项目树同步环节执行，不修改验收报告提交校验。版本支持数字点分形式、可选 v 前缀及括号构建号；未知版本顺序不猜测。时间采用报告提交时间，修订采用更新提交时间。历史版本保留各次提交快照。

## 数据安全与边界

- 只使用项目树专用服务、页面和 `project_config_records`，新增字段存于原有 `raw_json`，不需要改公共表结构。
- 不改验收报告、待办、接口测试、飞书通知的业务处理；不再自动将 A1160 的便签复制给其他项目。
- AI 必须给出逐字原文依据，非法动作或缺乏依据时整次分析不应用。链接原文保留，但不自动访问链接内容；超过 30000 字的报告显式报错，不静默截断。
- AI 是语义提取器，原文依据校验并不能证明语义百分之百正确；历史整理必须人工核对预览。
- 保存时检查并发修改；旧浏览器缓存不能覆盖新版服务端台账。
- 测试覆盖版本排序、继承与补交、群体隔离、人工项更新、80% 边界、废除与历史不可变、原文校验、低版本保护和重复同步。
