# ChangeLog - TestCase Generation

## 2026-05-06

### Changed
- **Review Stage Workflow**: 智能测试用例生成流程从三段扩展为四段，新增“用例评审”阶段；用例生成完成后可以继续进入评审工作台，而不是只能停留在 Excel 风格预览页。
- **Role-Based Case Review**: 新增产品经理、开发、测试、美术四个评审角色。每个角色都带有独立的身份 MD，AI 会结合身份说明、需求原文、需求点与当前用例集输出结构化评审意见。
- **Review Result Persistence**: 用例评审结果已纳入测试用例生成历史记录，保存或更新记录时会一并持久化，后续重新打开历史详情时仍能继续查看已有评审结论。
- **Generation Review Handoff**: 用例生成阶段新增“进入用例评审”入口，生成过程中如重新发起用例生成，会自动清空旧评审结果，避免旧评审结论误绑定到新一轮生成内容上。
- **Progress Tag Stability**: 生成进度预览右上角状态标签进一步压缩为“持续生成”，并继续收紧了标签的宽度约束和单行布局，减少窄空间下出现自发换行的概率。
- **Multi-Role Batch Review**: 用例评审页改为“多角色参与式评审”。四个角色卡片现在可单独切换“参与 / 不参与”，点击“开始评审”后会按参与角色并行完成多轮评审，不再需要用户逐个角色手动确认。
- **Review Consensus Summary**: 批量评审完成后，评审页会自动汇总多角色意见中的重合点和差异点，分别展示共识项与各角色独有关注点，方便快速判断哪些问题值得优先采纳。
- **Review-Driven Case Optimization**: 评审页新增“根据评审意见智能优化用例”能力，系统会结合多角色评审结果对当前用例集进行增补、合并和去冗余；优化完成后会清空旧评审结果，提示重新发起评审确认最终质量。
- **Optimized Case Preview**: 智能优化用例完成后，页面会直接回到用例预览区展示优化后的最新结果，并通过“初始保留 / 优化调整 / 优化新增”状态标签区分优化结果与原始用例，同时补充被移除用例的提示。
- **Tester-Guided Requirement Decompose**: 需求拆解和智能增强拆解阶段现在会显式注入测试角色身份 MD，并把拆分粒度稳定规则写进 prompt；同时将拆解类 AI 调用温度进一步降低，减少同一需求多次拆分时数量明显漂移的问题。
- **Background Generation Recovery**: 测试用例生成运行态已抽到全局 store 托管。用户在生成过程中切到其他页面后，重新回到“智能测试用例生成”页时仍能恢复当前批次进度和已生成结果，不会因为页面切换丢失生成上下文。
- **Assistant Task Shortcut**: 智能助手悬浮按钮现在会在“测试用例生成”或“剧集播放接口测试”有进行中 / 可恢复任务时显示对应状态；打开智能助手弹窗后，输入区左侧会出现“查看当前任务”快捷按钮，可一键返回正在运行或刚生成完结果的任务页面。
- **Stage Undo Mechanism**: 在用例生成、用例评审、评审优化三个关键阶段新增单步回退能力，支持撤销本轮生成、恢复上一轮评审结果，以及撤销本轮优化回到优化前状态，降低误操作后的返工成本。

## 2026-04-28

### Added
- **Direct Generator Entry**: 仪表盘中的“测试用例生成”卡片现在会直接进入“智能测试用例生成”页面，减少先进入历史页再二次跳转的操作成本。

### Changed
- **Generator Page Redesign**: 智能测试用例生成页面重构为更贴近平台后台风格的布局，统一了页头、步骤区、录入区、结果预览区和操作区的视觉层级。
- **Workflow Status Cards**: 原有默认步骤条替换为三段式流程状态卡，分别展示“已完成 / 进行中 / 待开始”状态，让需求输入、需求拆解、生成完成三步的当前进度更直观。
- **Flatter Workflow Cards**: 三段式流程状态卡在保持宽度不变的前提下进一步压缩高度，整体更扁平、更轻量，减少步骤区对页面首屏空间的占用。
- **History Page Localization**: 测试用例生成历史页完成中文化整理，页面标题、筛选项、列表列名和空状态文案统一调整为中文业务表达。
- **Requirement Link Input**: 需求输入页移除“建议内容 / 生成方向”说明卡，改为提供独立的“需求链接”输入框，便于补充飞书文档、Jira 或其他需求地址。
- **Feishu Doc Decompose**: 在需求链接中填入飞书 Wiki 或 docx 链接后，点击“开始需求拆解”会先读取文档正文，再用读取到的真实需求内容执行拆解，并将正文回填到页面供后续增强拆解继续使用。
- **Link-Only Decompose**: 需求拆解支持仅通过需求链接触发，不再强制要求用户先输入需求描述，便于直接粘贴飞书需求文档后一步完成读取与拆解。
- **Feishu Doc Type Compatibility**: 飞书需求链接读取逻辑已区分新版 `docx` 与旧版 `docs/doc` 文档，避免将不同文档类型错误地走同一读取接口；当文档未授权给当前飞书应用时，会返回更明确的权限提示。
- **Decompose Action Alignment**: 需求拆解阶段的“AI 智能增强拆解”和“确认并生成聚焦用例”按钮已统一尺寸和高度，避免操作区按钮视觉不齐。
- **MiMo Capability Routing**: 测试用例生成链路新增 `testcase_decompose`、`testcase_smart_decompose`、`testcase_generate` 三个独立 AI capability，需求拆解、增强拆解与用例生成可单独切到 MiMo，而不影响其他模块的默认 AI provider。
- **Split Analysis Workspace**: 需求拆解阶段新增当前模型提示，并将 “AI 需求分析结果” 调整为左右双栏：左侧展示本次拆解使用的需求原文，右侧展示拆分后的需求点卡片，便于并排核对。
- **Requirement Card Polish**: 右侧需求点卡片缩小了内边距与文字密度，并在鼠标悬停时增加轻微抬升和阴影，增强层次感但不影响整体后台风格。
- **Inline Smart Enhance Merge**: AI 增强拆解结果不再单独占用一个新模块，而是直接并入右侧需求点区域展示；新增需求点以红色卡片高亮，统计信息和“应用合并结果”操作也收口到同一区域。
- **Short Drama Analyzer Injection**: 需求拆解与增强拆解现在会先识别是否属于短剧类 App；命中后，会参考短剧 analyzer 的产品结构上下文，并先筛掉运营策略、投放目标、泛化体验等非项目功能层内容，只保留可直接生成测试用例的功能需求点。
- **Short Drama Badge**: 当需求拆解命中短剧 analyzer 时，需求原文模块会在“原文输入”角标左侧额外显示“短剧需求”角标，方便直接确认当前是否套用了短剧需求判定逻辑。
- **Smart Decompose Analyzer Reuse**: AI 智能增强拆解现在会优先复用首轮拆解已命中的短剧判定；只有首轮未命中时才会基于原文再次判断。若第二轮补判命中短剧需求，也会继续参考 analyzer 并同步点亮页面中的“短剧需求”角标。
- **Incremental Excel Preview**: 点击“确认并生成聚焦用例”后，页面会立即进入生成预览界面，并按需求点逐批把新生成的测试用例实时补充到下方 Excel 表格中；用户可以在后台持续生成的同时查看、滚动和核对已完成结果。
- **Requirement-to-Case Mapping**: 生成预览表新增“来源模块 / 来源需求点”列，每批需求点生成完成后，会把该需求点与对应测试用例一起写入 Excel 风格预览，方便核对每个需求点实际产出的用例集合。
- **Short Drama Analyzer For Generation**: 当需求被判定为短剧类需求时，测试用例生成阶段也会继续参考短剧 analyzer 的产品结构和关键业务链路，而不只是在拆解阶段使用 analyzer。 
- **Progress Card Loading State**: 生成预览界面的需求点进度卡片新增了更明确的 loading 反馈；当后台正在为某个需求点生成用例时，顶部状态标签和对应需求点卡片都会显示旋转中的生成态图标。
- **Progress Tag Overflow Fix**: 调整了生成预览中需求点状态标签的排版，`生成中` 标签现在会保持单行显示，并且不再被左侧长文案挤压导致换行超框。
- **Progress Header Tag Wrap Fix**: 生成进度预览右上角的状态角标区已改为更稳定的自适应换行布局，并收紧了“后台持续生成中”标签的图标与间距，避免在窄空间下继续拥挤超框。
- **Compact Generating Tag**: 生成进度预览右上角的长状态标签进一步压缩为更紧凑的“生成中”，并限制了标签宽度与溢出表现，避免继续挤占头部空间。
- **Selectable Smart Additions**: AI 智能增强补足出来的新增需求点卡片现在默认高亮且处于选中状态；点击卡片可取消选中并置灰。后续生成用例时，会按“基础需求点 + 仍处于选中状态的新增需求点”组合生成，不再强制把所有增强项全部带入。
- **Header Generating Tag Single-Line Fix**: 生成进度预览右上角的“生成中”标签进一步锁定为单行内容，修复 Element Plus 内层内容在窄宽度下仍可能自行换行的问题。
