# TestCenter 平台部署与运行指南

本仓库是一个基于 Vue 3 + Go + k6 的核心业务流程验证平台。你可以通过以下步骤在新的电脑上快速部署并运行本项目。

## 1. 基础环境库 (Prerequisites)

在开始之前，请确保你的系统中已安装以下工具：

- **Git**: 用于克隆项目代码。
- **Node.js (v16+)**: 前端开发环境，推荐使用 LTS 版本。
- **Go (v1.25+)**: 后端转发逻辑及 API 代理环境。
- **k6**: 用于执行性能和核心流程验证脚本。
    - macOS: `brew install k6`
    - Windows/Linux: [下载二进制文件](https://k6.io/docs/getting-started/installation/) 并添加到系统变量。

## 2. 代码拉取 (Cloning the Project)

```bash
git clone https://github.com/Stroke-H/TestCenter-Vue3.git
cd TestCenter-Vue3
```

## 3. 一键启动 (Running the Project)

本项目提供了一个全自动启动脚本 `start.sh`，它会自动执行以下操作：
1. 检查环境变量 (Node, Go, k6)。
2. 如果缺失 `node_modules`，自动执行 `npm install`。
3. 如果缺失 Go 依赖，自动执行 `go mod tidy`。
4. 自动检测并清理 8080 (Go) 和 5173 (Vue) 端口占用。
5. 同时启动前后端服务。

**运行命令：**

```bash
chmod +x start.sh  # 仅第一次运行时需要
./start.sh
```

### 配置固定访问入口

如果你希望其他机器访问更稳定，需要固定的是**用户打开的入口地址**，例如 `testcenter.lan` 或可用的 `strokeh.local`。IP 地址可以变化，但用户手里的入口不应该变化。

项目根目录创建本地配置文件：

```bash
cp .env.lan.example .env.lan.local
```

然后填写固定入口，例如：

```bash
TESTCENTER_LAN_HOST=testcenter.lan
TESTCENTER_FRONTEND_ORIGIN=http://testcenter.lan:5173
TESTCENTER_BACKEND_ORIGIN=http://testcenter.lan:8080
```

`start.sh` 启动时会优先读取 `.env.lan.local`；只有在未配置时，才会回退到基于 Bonjour/mDNS 的 `strokeh.local`。如果配置的是固定域名，启动脚本会检查它是否解析到当前这台 Mac 的局域网 IP；如果配置的是 IP 字面量，脚本会把它当作 fallback 模式并提醒这不是长期稳定入口。

## 4. 访问端口 (Access Ports)

- **本机前端界面**: [http://localhost:5173](http://localhost:5173)
- **本机后端服务 (Go)**: [http://localhost:8080](http://localhost:8080)
- **固定局域网访问**: 同一局域网的其他设备优先访问启动脚本输出的 `Stable LAN Frontend`，当前默认是 `http://strokeh.local:5173/dashboard`。这个地址跟随本机 Bonjour/mDNS 主机名解析，IP 变化后仍可保持同一个访问入口。
- **IP 备用访问**: 启动脚本也会输出 `LAN IP Fallback`，仅用于排查 mDNS/Bonjour 被网络环境屏蔽的情况。不要让其他设备访问 `localhost`，因为它会指向对方自己的电脑。

### 4.1 `strokeh.local` 的适用边界

`strokeh.local` 依赖 Bonjour / mDNS，不是普通 DNS 域名。它能否在另一台设备上打开，取决于访问者设备与当前局域网环境，而不只取决于本项目是否启动成功。

要让 `http://strokeh.local:5173/dashboard` 稳定可用，至少需要满足：

1. 访问设备和本机在**同一局域网广播域 / 同一网段**内。
2. 路由器、AP、交换网络**没有开启 client isolation / AP isolation / 访客网络隔离**。
3. 网络允许 **mDNS / Bonjour 组播**，即 UDP `5353`（`224.0.0.251` / `ff02::fb`）不会被阻断。
4. 访问设备本身支持 `.local` / Bonjour：
   - macOS / iPhone / iPad：通常原生支持；
   - Windows：通常需要安装 Bonjour 服务；
   - Android / Linux：支持情况依浏览器、系统组件和网络环境而定。
5. 如果跨多个 AP、VLAN 或子网，需要网络设备支持 **mDNS reflector / repeater / gateway**，否则 `strokeh.local` 可能只在部分设备上可见。

### 4.2 怎样判断是不是 `.local` 解析问题

如果另一台设备：

- 能打开 `LAN IP Fallback`
- 但打不开 `http://strokeh.local:5173/dashboard`

那几乎可以判定是**那台设备的 Bonjour / mDNS 解析问题**，而不是 TestCenter 没启动。

如果：

- `strokeh.local` 和 `LAN IP Fallback` 都打不开

那通常说明是**网络路径问题**，例如不在同一网段、走了访客 Wi-Fi、开了 VPN，或者 AP/client isolation 阻止了局域网互访。

### 4.3 关于固定 IP 和固定域名

这件事**不能仅靠项目代码保证**。因为 `.local` 的解析权在访问者设备与网络环境上，不在 Vue/Go 服务进程里。

当前有两种稳定化方式：

1. **固定域名模式**：使用 `testcenter.lan` 或可靠的 `strokeh.local` 作为长期入口。用户始终打开同一个地址；如果本机 IP 变化，只更新域名背后的解析。
2. **IP fallback 模式**：直接使用有线网卡地址，例如 `http://172.16.3.144:5173/dashboard`。它适合排查和临时使用，但不满足“IP 变化后入口仍不变”的目标。

本项目当前保留 `strokeh.local` 作为默认固定局域网入口，是为了在 Apple 设备和标准 Bonjour 网络中获得最省事的开发体验；但它不等价于“所有设备、所有网络都能零配置访问”。

## 5. 项目结构说明 (Project Structure)

- `/src`: Vue 3 前端源代码（包含测试流程可视化编辑工具）。
- `/server`: Go 后端服务，负责 API 代理和 k6 任务分发。
- `/k6-scripts`: 存放各业务流程的 k6 核心验证脚本。
- `start.sh`: 核心启动脚本，支持优雅停机（Ctrl+C）。

---
**Tips**: 如果在非 macOS 系统运行，可能需要手动进入 `src` 执行 `npm run dev` 和 `server` 执行 `go run main.go`。
