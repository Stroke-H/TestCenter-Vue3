# TestCenter 开发者规范与要求汇编 (Dev Rule)

根据我们在交流过程中您的直接诉求及沉淀下来的**全局核心开发准则**，我以此为基准为您制定了以下专属的开发者规范清单，后续任何功能迭代或重构都需要严格遵循：

## 一、 技术栈与架构选型
1. **统一前端生态**：前端强制使用 **Vue 3 + TypeScript + Vite**，基于 **Pinia** 进行所有状态（如报告集）的统一持久化与状态管理。UI 层统一采用 **Element Plus** 现代化组件框架。
2. **轻量化中心枢纽**：后端一律使用 **Go + Gin** 构建常驻 HTTP/WebSocket 服务，仅提供工具集的编排（如调用系统进程 `os/exec`）与静态文件映射。
3. **性能并发引擎**：深度集成 **K6** 作为标准性能/接口压测工具，输出标准化的 HTML 图表报告以便前端 iframe 呈现。

## 二、 基础代码格式规范
1. **命名严谨性**：
   - 文件与目录结构保持语义化，组件文件大驼峰 `PascalCase`（如 `TestReports`）。
   - 代码层：变量及防抖必须采用小驼峰 `camelCase`，TypeScript 接口（Interface）与类使用 `PascalCase`。
   - 严禁出现难以阅读和维护的非标准简写。
2. **设计美学 (UI/UX)**：
   - 功能页面必须紧密贴合（或超过）现有平台的 Modern 现代风格和高级感。
   - 页面需包含侧边栏导航、面包屑、状态过滤以及响应式布局等通用骨架。
   - 善用徽章（Badge/Tag）、卡片圆角以及阴影层级，以保证视觉上清晰耐看。

## 三、 执行纪律与核心自检流 (Core Workflow)
1. **每次修改必须自检（最高红线）**：
   - 每次代码修改完成后，**必须先编译（或执行脚本）自检一下，确认无报错之后，再交付确认修改**（遵循全局规则的第 10 点）。
2. **最小化侵入原则**：
   - 在追加新功能或者修复 Bug 时，优先遵循**最小化改动**原则，只需变更业务流相关的代码，不随意推翻无关业务的历史重构。
3. **注释要求清晰度**：
   - 对 Vue 的 Composition API 与后台 Go 并发引擎（WebSocket 通信链路等），都要做到逻辑段落逐行注释，并说明可能产生的阻塞卡点，坚决消除"黑盒"。

## 四、 自动化生命周期保证
1. **脚本一键闭环**：
   - 启动流程中，统一采用 `start.sh` 执行完整的前后缀项目冷启动与依赖监控。
   - 启动时须自动化检测必备依赖（Node.js, Go 工具链, k6 引擎 等），如无则智能安装。
2. **端口僵尸清理**：
   - 对诸如 `5173` (Vite) 或 `8080` (Go Gin) 被误占用情况需要实现自动化侦测。对重复模块主动抹杀 (`kill`) 并干净地重启以防多开冲突。
3. **断网/离线持久性**：
   - 本地产生的数据（如测试结果）在不接入数据库的情况下，应用 `LocalStorage` + `Pinia` 做到跨页签、跨生命周期的自动化本地存盘。

## 五、 特殊处理及性能考量 
1. **前端错误边界**：针对未知状态（暂无图表、加载中止、接口未捕获异常），在前端必须辅以优雅的兜底处理（如弹窗反馈与 `el-empty` 空状态界面）。
2. **引擎状态解耦**：Go 层必须妥善利用 Go 的并发信道 `goroutine` 与客户端隔离运行状态（`Stdout` 实时桥接展示），并在完成时精确流转状态给前端，确保任何长耗时测试均不会打断或阻塞后台其余主进程。
